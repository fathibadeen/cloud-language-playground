# إدارة وربط Meta WhatsApp Cloud API من لوحة المدير — Embedded Signup حقيقي

## المبدأ
إضافة فقط، بلا إعادة بناء: نفس الشركات والوكلاء وقاعدة المعرفة والمحادثات والويب هوك الحالي. الربط يتم من لوحة المدير لكل شركة على حدة (Embedded Signup الرسمي من Meta) — لا توكن في الواجهة ولا localStorage، ولا بيانات وهمية.

## الوضع الحالي (مؤكد من الكود والقاعدة)
- whatsapp_accounts موجود (company_id, provider, phone_number, business_account_id, agent_id, status, is_active) — يُعاد استخدامه، صف لكل رقم.
- provider_credentials موجود (secret_payload، بلا صلاحيات للعملاء — service_role فقط) — يُستخدم لتخزين توكن كل شركة مشفرًا.
- الويب هوك يعمل فعليًا على /api/public/webhooks/whatsapp (تحقق توقيع + تخزين webhook_events + معالجة) — يبقى كما هو: هذا هو المسار المطلوب في بنيتنا للنقاط العامة، ولا يُنشأ مسار مكرر.
- ingestWhatsappMessage موجود (عميل + محادثة + رسالة + رد AI من الوكيل وقاعدة معرفة الشركة) — يُعدّل فقط ليستخدم توكن الشركة بدل المفتاح العام.

## 1) الإعدادات (secrets — عبر نموذج آمن)
META_APP_ID, META_APP_SECRET, META_CONFIG_ID, META_REDIRECT_URI, META_GRAPH_API_VERSION — وما زال WHATSAPP_VERIFY_TOKEN / WHATSAPP_WEBHOOK_SECRET يُستخدمان للويب هوك. قبل إدخالها: كل زر ربط يعرض "Meta WhatsApp غير مُهيأ بعد" بأسماء الحقول المطلوبة، ولا تظهر حالة "متصل" إلا بعد اتصال حقيقي.

## 2) قاعدة البيانات — هجرة 0005
- whatsapp_accounts: إضافة phone_number_id و verified_name (nullable).
- provider_credentials: صف scope='whatsapp' لكل شركة يحفظ { access_token, expires_at } مشفرًا AES بـ ENCRYPTION_KEY (يُولَّد تلقائيًا).
- لا جداول جديدة أخرى — لا تكرار.

## 3) المصادقة (Embedded Signup) — src/lib/meta.server.ts + meta.functions.ts
- getMetaConfig (createServerFn عام): يعيد appId/configId/graphVersion/redirectUri فقط.
- startWhatsappConnect (مدير عام super admin): يستقبل companyId → يفتح نافذة Meta (window.FB.login بـ configId) مرتبطة بالشركة المختارة.
- عند العودة: الرمز (code) يُستبدل في السيرفر بتوكن أعمال طويل العمر → قراءة WABAs وأرقامها من Graph API → إنشاء/تحديث صف whatsapp_accounts للشركة المختارة → حفظ التوكن في provider_credentials → تسجيل الاشتراك بالويب هوك على WABA (subscribed_apps).
- كل فشل رسالة عربية واضحة: فشل تفويض Meta / توكن غير صالح / الرقم غير متاح / الرقم مستخدم لشركة أخرى / تحقق النشاط مطلوب / خطأ Meta API.

## 4) لوحة المدير — تبويب "WhatsApp" (في admin.tsx الحالي بلا تغيير تصميم)
- جدول بكل الشركات: الاسم، حالة واتساب (غير متصل / متصل / يحتاج إجراء / خطأ)، الرقم، اسم WhatsApp Business، الوكيل المرتبط، تاريخ الربط.
- أزرار لكل شركة: ربط WhatsApp، إدارة، اختبار الاتصال، فصل الاتصال.
- صفحة تفاصيل الشركة: الحالة، Business Account، WABA ID، الرقم، Verified Name، الوكيل المعين، قاعدة المعرفة، آخر ويب هوك، رسائل اليوم، محادثات اليوم، الأخطاء.
- اختبار الاتصال (سيرفر): التحقق من التوكن و WABA و phone_number_id عبر Graph API + الوكيل المعين.
- فصل الاتصال: تعطيل الصف وإزالة الوكيل المعين وحذف التوكن — المحادثات والرسائل السابقة تبقى.
- "تفعيل الوكيل": اختيار وكيل موجود للشركة (لا وكيل جديد) وربطه بالرقم.

## 5) الإرسال والاستقبال
- sendWhatsapp: يجيب التوكن المفكوك لـ phone_number_id من provider_credentials، يرسل عبر Graph API بنسخة META_GRAPH_API_VERSION، ويخزن بنظام المحادثات الحالي.
- الاستقبال: نفس الويب هوك — phone_number_id → الشركة → الوكيل المعين → قاعدة معرفتها → رد AI → إرسال بالتوكن. needs_human يوقف الردود كما هو. التكرار (idempotent) كما هو.
- العزل كامل: لا تعرّف الشركة من الواجهة أبدًا؛ من phone_number_id في قاعدة البيانات فقط، وRLS كما هو.

## 6) صفحة واتساب لدى العميل
تبقى كما هي مع تحسين بسيط: تعرض الحالة الحقيقية (متصل/بانتظار ربط المدير) — الربط نفسه يصبح من لوحة المدير، فلا حاجة لنموذج الطلب اليدوي إلا كتوثيق (يُسجَّل تلقائيًا في connection_requests عند الربط).

## 7) قائمة الاختبار (بعد إدخال مفاتيح Meta)
1. المدير يختار شركة → ربط WhatsApp → Meta → اختيار Business → اختيار الرقم → عودة للمنصة.
2. الحالة "متصل" مع الرقم والاسم الصحيحين.
3. اختيار وكيل → تفعيل.
4. رسالة واردة → ويب هوك → الشركة الصحيحة → الوكيل الصحيح → قاعدة المعرفة الصحيحة → رد AI عبر Meta.
5. الرسالة تظهر في المحادثات الحالية.
6. اختبار الاتصال يفشل برسالة واضحة عند توكن غير صالح.
7. فصل الاتصال يحافظ على المحادثات.
8. ويب هوك مكرر لا يضاعف الرسائل.
9. شركتان: عزل كامل بين الأرقام والوكلاء وقواعد المعرفة.
